# 本机同一主题：旧页不能覆盖新首答

## 实页复现

用 c81c5fc 在同一隔离 Windows Edge 配置打开合成主题的两个页签。A 进入规则题并保存正确首答；B 仍停在之前的讲解核对。B 仅修改文字核对草稿，旧版会把整条主题旧副本写回，本机首答计数从 1 变 0，A 刷新后也找不到。不是题目错误或 AI 行为。

## 修复

正式保存必须在 IndexedDB 同一个写事务内比较当前记录与本页读到的版本。沿用现有更新时间，成功写入至少前进 1 毫秒；同页同对象保存排队，不靠系统时间猜哪一页更新。冲突不自动覆盖、合并或重试。沿用恢复区和本机备份：提示先导出本页尚未保存的修改，再刷新读取新版。保留原期限、格式与模型。

## 定向验收

同一两页签走查修复后，B 屏上保留键入内容、只能导出不盲重试；下载的合成备份内含 B 的核对草稿，A 的同一个首答仍在。B 刷新后恢复 A 已保存的首答。此备份是 B 的本地恢复副本，不表示已经合并到 A。定向 Node 21/21；新增一项浏览器事务回归，检查相同旧基准只能有一个成功写入。无真实模型请求、花费或真实数据。

## 第一次 CI 审核后的修正

保存材料新版时会先保存同一主题的临时副本。恢复提示按主题 ID 归属，不再要求是同一个 JavaScript 对象；版本比较仍按此次写入所读的旧基准。隔离 Edge 注入普通写入失败后，原材料、已存讲解和编辑草稿保留，恢复区出现并可重试。解除故障后，重试保存草稿，再显式保存新版，结果只新增一个材料版本。

沿原两页签路径，旧页仍不能覆盖或盲重试；能导出未写入的草稿，刷新后原首答 ID 不变。冲突提示明确要求确认备份已下载再刷新或关闭，未导出的修改会丢失。两条走查均无真实模型请求。
