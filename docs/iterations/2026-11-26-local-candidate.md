# 知而能讲 · 1.0.0-rc.1 本地候选

从一段确认过的讲解，找到一个能回去核对的具体问题，再把修正放进一道改变了条件的题。此次候选用于 Windows 本机体验和作品展示。A、B 和本批分别由 [#43](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/pull/43)、[#44](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/pull/44)、[#45](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/pull/45) 交付。最终合并版本及 CI 见[当前状态](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/blob/meta/master-state/docs/master/CURRENT_STATE.md)。

## 产品案例与改版

之前的首页把导入、文件限制和学习偏好排在讲解前。旧反馈可以跳回原文，但工作台的“当前重点”无论处于什么阶段都只能看证据。我们把“下一步还能做什么”落到具体对象：待确认的讲解、这一项的局部重讲、同一道题的作答草稿，或本轮总结。[原首页](v1-experience/home-before.png) · [现首页](v1-experience/desktop-home.png)

视觉层级借鉴 Apple 的留白和单一主动作。桌面交互参考 ChatGPT Desktop 的直接输入方式，把导航做成可收起的侧栏，讨论输入框与发送按钮合在一起。首页去掉重复标语、步骤说明与示例卡，手机保留底部讲解按钮。讨论是否发送材料、首答是否参考、反馈所用版本仍在决定发生的位置显示。[桌面工作台](v1-experience/desktop-workspace.png) · [390px 首页](v1-experience/mobile-home.png) · [Apple 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles) · [ChatGPT Desktop 官方页面](https://chatgpt.com/download/)

来源版本、目标原句、确认文字、报告与题目各自留存。程序由这些记录推导当前动作。示例中“只需要实名”漏掉了截止时间。用户从引用回到同一个问题，重讲两个条件，回答 18:05 的新情境。若已经见过普通题，入口会解释这道题只能继续普通练习。标记题目有疑问会撤下通过状态。限规则出题和额外参考自报都限制了这份证据的适用范围。[反馈与下一步](v1-experience/desktop-feedback.png) · [理解档案](v1-experience/record-desktop.png)

长文件现在可在原材料的修订入口重新导入，从提取预览选下一段。保存后旧报告仍指向旧选段。备份包含采用的文字及定位。这样可以接着读同一文件，并保持既有保留范围。用户要自己再次提供原文件。

## 验证回执

- **Windows 与真实入口。** 本机启动器进入 ready，未配置 Key 的 `/demo` 返回 200，服务正常关闭。临时 Edge 配置经浏览器原生采集接口获取一个音轨，从 live 到 ended，未采样或传输音频。麦克风来源的硬件身份及录音质量没有独立确认。Computer Use 限制借资源管理器执行命令脚本，因此未实测 Explorer 鼠标双击 `Start-Study.cmd`。人工复验可从仓库目录双击，查看默认浏览器，结束时在启动窗口按 Enter。
- **桌面与 390px Edge。** 用同一份合成门禁材料执行初讲、确认、原文核对、补学、局部重讲、新题首答、刷新、v6 编解码恢复和题目复核。验证了重点卡跳向确切任务，修复了重讲的“已表达”盖过独立首答总结的问题。另一遍先打开普通题再重讲，确认旧题给出明确提示，答对仍为普通题。窄屏第一屏可以直接讲解；桌面侧栏开合可用。
- **文件、演示与反馈。** 未配置模型时重新导入超过 5,000 字的合成 TXT，截取尾段后保存并采用新版本。备份可解码出旧版本和带文件名的新选段，未包含被舍弃的章节。预写课程从错误解释走到修改、作答及结果。本地反馈导出只有版本、环节、影响和说明。上述路径发起模型请求 0 次。
- **工程检查。** Windows CI 集中覆盖共享代码。更新旧测试的 DOM 模拟，并移除锁定字体、按钮文案和说明逐字顺序的重复断言。保留导入可达、输入标签、对比度、题目暂停和历史来源的行为检查。产品实现对应 [f258b9b](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/commit/f258b9b3cb85c360a5cced8e2c3c90d15404ebec)。[首批走查](2026-11-26-learning-home.md) · [证据闭环走查](2026-11-26-understanding-record.md)
- **语音与学习效果。** 两条已归档合成 WAV 在当前工具中无法试听，独立听审仍待补。历史固定 16 次比较已封存。生产转写沿用原配置，本轮无新增付费模型调用。真人参与者和延迟迁移结果均尚未取得。[ASR 比较](../research/asr-comparison-2026-11-19/README.md) · [形成性研究方案](../research/v1-formative-study.md)

## 反馈怎样进入下一版

页脚可生成本地反馈文件。学习者自行决定是否交给维护者。整理时用版本、复现动作、期望、实际结果和影响建条目，不要求提交学习文本或录音。先处理丢失回答、错绑来源、误把普通答案计为独立等问题，再处理阻碍完成任务的操作，最后处理措辞与外观建议。合成材料能复现就只验证对应路径。关闭条目时附修复提交、证据和影响版本。按同一失败在多少个受观察任务中出现决定优先级，保留分母。

| 下一项 | 依据与验收 |
| --- | --- |
| 验证学习者能自己找到反馈原句并重讲 | 工程路径已跑通。获准后由研究主持人观察首批任务，记录提示前能完成的人次和卡住的位置 |
| 检验迁移题的解释质量 | 目前本机题支持的规则有限。用预冻结平行题核对未见、首答、理由、参考与 24–48 小时回访，评审按同一量尺盲评 |
| 补证 Windows 日常安装及 ASR 维护 | 维护者在可交互 Windows 上用鼠标启动并试听两条音频。保留错词、否定和数字的实际听审记录，生产切换前另行决定 |
