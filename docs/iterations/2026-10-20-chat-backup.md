# 聊天恢复、备份恢复与页面精简

批次：2026-10-20。用户授权自主决定方案、实现、GitHub 留痕与交接，减少冗余验证。

跟踪：[Issue #8](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/issues/8)。本批 PR 与最终 CI 由该 Issue 关联；最终合并结果记入 canonical `meta/master-state`。

## 行为

普通聊天在发送前保存问题、模式、当时的短历史和请求状态。失败／刷新后展示显式重试；重试沿用原问题，不追加重复用户消息，不自动发送。第一次自动讲解和补学指令仍不冒充用户输入。异步保存前即锁定操作，避免快速双击。

收到回复但本机保存失败时，保留内存中的成功结果，通过“重试保存”或导出继续，不为此重新请求模型。无法确认服务器结果时显示未完成状态；再次重试是新请求，不能保证服务商未处理上一请求。跨标签页持久去重仍未实现。

主题顶栏和学习记录可导出 v1 JSON。记录列表的“导入备份”在本机检查文件并预览；明确确认后，以单次 IndexedDB `add` 建立新副本，不覆盖或合并现有主题。取消、格式错误、写入失败不插入半份记录。支持原有 v1 导出，包括旧 `apply` 记录；新练习记录、草稿、普通聊天恢复状态一起保存。

只新建主题 ID；原始来源、讲解、转写、报告 ID 与录音字节保留。尝试删除标记改为内存对象标记，避免同一原始讲解 ID 在恢复副本中被误当作已删除。备份文件上限 128 MB；不支持任意聊天平台导出或损坏报告的自动修复。恢复不调用模型、不重置服务端费用账本。

原主题仍按 `createdAt` 七天到期。恢复副本保留原日期，另记 `restoredAt`，从用户确认恢复时起保留七天；预览与数据说明明确展示该规则。打开应用时清理仍沿用原行为。
