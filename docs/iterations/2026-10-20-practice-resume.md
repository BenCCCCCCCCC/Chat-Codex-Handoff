## 优先级依据

审核真实产品代码发现：

1. `topic.apply` 只有一份，新题覆盖旧题；回答与普通聊天混在一起，再次作答会回到 learn 模式。
2. 重新打开时使用 IndexedDB 主键顺序的最后一条，并非最近学习主题；只显示学习区，不恢复转写核对或情境练习。

本批先完成“理解 → 应用 → 反馈 → 再答 → 下次继续”的闭环。沿用既有材料、Tutor 接口和界面语言，不增加多源 UI 或新模型服务。Issue #3 研究协议保留，按用户最新功能优先指示后移。

## 实现

- 独立练习区：出题、原题、作答、反馈、再次作答与旧题选择。
- 每题保留多次回答；原题作为每次评价的 focus 发送，不依赖普通聊天最近六条上下文。
- 练习不写入普通聊天，不覆盖讲解录音；重复提交已有成功反馈的相同回答复用本地结果。
- 草稿 350ms 防抖保存，失焦和导航前刷新保存；提交前保存回答。失败／刷新不会自动发模型请求，显式重试保留同一回答记录。
- 模型响应已到而本机保存失败时，结果保留在内存，继续使用既有保存恢复／导出入口。
- 主题增加 `updatedAt` 与 `resume`；记录按活动时间排序，恢复学习／核对／练习位置。录音完成会记录对应 attempt；打开历史讲解会保存续接位置。
- 旧 `topic.apply` 读入新的练习记录，原字段保留。新增数据为既有主题对象的可选字段，无 IndexedDB 版本迁移；导出 v1 包含练习记录。七天到期仍按原 `createdAt`，没有延长保留期。
- 录音时隐藏练习与回答，保持既有提示条件；普通录音／内容诊断机制不变。
