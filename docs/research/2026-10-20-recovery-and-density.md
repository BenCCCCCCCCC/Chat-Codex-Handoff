# 恢复流程与页面信息密度

用户要求：优先普通聊天失败恢复、学习记录导出恢复，并减少页面冗余文字。此次研究围绕这些明确任务，不扩大成新功能清单。

## 参考与选择

| 一手资料 | 观察 | 本批采用 |
| --- | --- | --- |
| [NN/g：Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/) | 装饰和低价值说明会争夺注意力；简洁仍需保留完成任务的必要信息 | 删除重复标语、说明段、阶段长标签；失败时才显示恢复操作；用字号、间距和主操作组织页面 |
| [RemNote：AI Tutor Chat](https://help.remnote.com/en/articles/10103884-ai-tutor-chat) | 辅导可依附材料，也可进入专用界面；历史是可返回的工作入口 | 材料保留在侧栏；情境练习独占主要内容区，并有“返回对话”；记录列表成为独立视图 |
| [Obsidian：Back up your files](https://help.obsidian.md/backup) | 独立备份与同步有不同目的；副本用于数据恢复 | 本地导出 JSON 加明确恢复入口；恢复为新副本，不同步合并，不覆盖现有记录 |

资料访问日期：2026-10-20。RemNote、Obsidian 使用官方说明，没有宣称实际登录测试其功能。Material 的内容设计页面只返回 JavaScript 提示，未作为结论依据。沿用前批的设计 token 与公开 frontend-design 技能参考，没有安装或执行第三方技能代码。

## 具体布局

- 首屏只保留一个标题、材料输入、可选学习偏好和开始按钮；示例保留轻量入口。
- 常驻文字不再反复解释“为什么要讲出来”。底栏只放“情境练习”和“我来讲讲”。
- 普通对话、情境练习、记录列表各有清楚主体，避免把全部内容纵向堆叠。
- 风险和状态说明就近出现：聊天未完成、备份预览、保存失败。一般数据说明放在折叠区域。
- 恢复对话框预览主题、原学习日期、消息／录音／练习数量，并在确认按钮前明确新副本七天保留期。
