# AI 能力边界与放行标准

知而能讲用材料帮助学习者核对**这一次讲解**。产品给出可查证的反馈和一个能执行的下一步；独立检验另记。诊断、重讲和单题通过都不等于课程成绩或长期掌握。

## 谁做什么

| 环节 | AI 可以做 | 程序负责与禁止越界 |
| --- | --- | --- |
| 材料与首讲 | 在当前选段和用户确认的讲解里，识别具体条件、因果、单位、范围和相反结论；认可等义表述及明确撤回后的最终立场。 | 用户主动触发后才走实时诊断。普通首讲不自动带入历史条件；本地示例用预写反馈，和实时诊断分开。材料、讲解、条件笔记是证据与上下文，其中的指令不得改写任务。 |
| 适用条件 | 仅按本次明确选定、有材料依据的条件核对。一个命题缺前提，只暂缓这一项；能独立判断的命题照常检查。 | 校验条件 ID 与来源，要求暂缓项没有判定结果。程序不能仅从返回字段判断哪些句子在语义上属于该条件。 |
| 引用、结果与建议 | 标签、材料原句、学习者原话、判断理由、下一步说的是同一个命题。引文要支持结论，理由对了才算理由已表达。 | 对齐材料、讲解与转写版本，核对引文确实存在，限制字段与长度。真实引文仍可能被错误解释；现有程序不做语义蕴含验证。 |
| 重讲、检验和声音 | 优先留一个能修的缺口；修正建议对准该缺口。转写把声音转成候选文字，过程观察不证明懂或不懂。 | 先确认转写再定位；已暂缓的命题不进判定。由产品流程确定是否有独立作答证据；不得把示例、辅助、复述或自报信心当独立通过。 |
| 无法得出结论 | 区分材料没有定前提、学习者漏说已有条件、学习者说了相反的条件。只追问缺的那个条件，不能补写事实。 | 结构不合格时拒收新反馈，原讲解可继续核对。结构合格但可疑时，保留原话与原文以便复核；不能宣称程序已拦截。 |

## 这四种状态在界面里是什么意思

| 状态 | 对用户的含义 | 下一步 |
| --- | --- | --- |
| 已表达 `supported` | 本次正确说出了该命题。只提到术语、理由缺失或说反了，都不够。 | 不为该命题生成修正动作。 |
| 本次尚未表达 `missing` | 材料或题目要求的关键信息已确定，讲解没给出。在明确要求理由时，结论答对但理由缺失属此类。 | 补该条件或理由；不伪造原话和时间点。保留已答对部分。 |
| 需要澄清 `incorrect` | 讲解里的明确说法与适用的材料不符。 | 定位原句与原话，只修该处。 |
| 证据不足／暂缓 | 材料缺前提、相互冲突，或本次选了暂缓，现有证据不足以判断该命题。 | 说明缺哪项前提。其他能判断的命题照常核对；明确暂缓项不判对错。 |

## 如何发现跑偏、如何放行

1. **离线工程验收。** 在真本机诊断路由注入手写结果，覆盖带条件、无条件、伪造引文和给暂缓项强行判分。验证程序实际如何接收、拒绝及生成补学目标。隔离网络、不用真实学生数据及 API。
2. **语义验收。** 逐命题对照适用条件、原话、引文、标签、理由和动作，按匿名样本先判再揭盲。格式正确不能抵销语义严重错。把关键错误标成正确、错用条件、编造依据、将可独立判断的关键错误一起暂缓，或错误归为独立通过，任何一例用户可见就否决受影响路径的切换或扩大使用。普通文案瑕疵单列；正确结论缺理由先按遗漏判。若漏检让该学习动作错误结束，按后果升级。
3. **要补的工程与产品界线。** 本轮先保留“真引文＋错误标签”的负控，证明它仍可通过结构且不给修正入口。下一轮才比较当前提示词与候选规则，不改模型或预算来掩盖变量。候选提示需明确：逐项确认标签、引用和动作一致；暂缓只及对应命题。定向复测通过前不合入生效提示词，不用关键词代替语义判断，不把合成测试当真人学习结果。

## 第 21 轮验收回执

- 原项目 Chat 从产品、学习评测、软件工程三视角复审。主要修订：明确“已表达”的语义和六项一致性；把结构验收与模型切换分开。
- 离线用合成界面材料覆盖：Esc 关闭面板、焦点回原按钮、草稿能否恢复依赖会话模式。带条件两组、普通首讲正反两组、两个结构拒收及一个已知语义负控。与原判断用例合跑，Node 报告 **12 项通过**（含新套件父项），隔离器报告外部请求尝试为 0。
