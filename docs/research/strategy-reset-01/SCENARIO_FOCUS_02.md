## 1. 最新方向与历史保留

用户说明：不一定做业务方向，更偏功能性或App形式，希望帮助普通人的学习、生活、工作。此前商家接单/报价比较不是当前优先推荐；AI推理游戏也不作为实用工具主线。它们不是被证明没有价值，而是与最新选型偏好不一致。

不要从用户个人项目经历选市场，不再读取其他个人项目来证明人群需求。不要要求AI轻用户安装Codex、配置API Key、学会Git或自行部署。Codex是我们的开发工具，不应是目标消费者的使用前置。

“学习、生活、工作都有帮助”不等于必须在一个MVP里同时做学习平台、日历、聊天、搜索和自动化。优先找一种可横跨场景的清晰功能，但首版只做一个完整、低风险任务。

## 2. 选型标准

以下是MASTER本轮设计准则，不是已经通过用户研究的结论：

- 有明确打开理由：我要准备一件事、掌握一点内容、练一次表达，而不是体验AI本身。
- 从熟悉的资料/操作进入：选择一张截图、一段通知、一份材料；不先要求写复杂prompt或维护知识库。
- 有可检查结果：必要事项有没有漏、用户能不能应用所学、表达有没有达到用户选定目标。
- 能重复使用但不刻意增加打卡压力；实际任务频率和AI使用频率分开。
- App形态只是交付方式，不构成创新；需要对比用户实际可用的普通工具、原生AI和直接竞品。
- 先能小范围实现并诚实说明限制；不预设零推理费用、全端支持或无限主动操作。

## 4. 候选A：个人事项准备助手（本轮优先研究，不是已定产品）

### 用户与场景

普通个人用户，已收到活动/学习提交/工作培训等明确事项通知，相关时间、步骤、要带/要交的材料分散在几份文本或截图中。会用相册、聊天和提醒，但不想为每件小事建项目。按“最近实际要准备过一件多资料事项”筛选，不凭学生/白领标签推定需求。

初期选低风险活动参与或普通材料提交一类场景。留学/移民法律、医疗用药、付款/理财等高风险情形不作MVP；不读取儿童或家庭成员材料作为默认。

### 产品功能与候选价值

把主动提供的资料组织成一张可执行的“这件事”卡：何时要做、之前需要完成什么、要带/提交什么、材料在哪里、哪些有歧义。原文明确要求与AI建议分开；“已准备”来自用户确认或可验证结果，不由文件存在猜测。

用户分享后续通知时，提出“这可能是同一件事的更新”、展示更改与冲突，确认后更新相应事项，不重复建多个无关提醒。不能仅因新文件时间晚就将其视为权威最新要求。

到需要处理时展示未完成准备项及原材料，而不是只发一个标题。主动提醒/日历写入需要明示授权，并允许关闭、延后、撤销；本轮没有创建任何提醒。

功能候选：选择资料 -> 来源可查的事项卡 -> 必要澄清 -> 可确认的准备清单 -> 后续变化合并 -> 需要时使用材料。不是整套任务管理、邮件监控、自动提交或万能生活Agent。

### MVP

先限定一种低风险事项、中文文本+用户选择的截图、单个人、来源/事项/材料/更改确认。只实现一个端和一种提醒/导出方式；不同时接邮箱/聊天/相册全库，不做多人协作、后台屏幕采集、账号凭据或自动付款。

移动端优先是设计建议，具体原生/PWA/桌面方案待一个界定好的实验选择；不能承诺所有平台分享、后台读取或通知能力一致。

### 实现与反证

模型提取语义、匹配事项、提出准备建议；确定性规则处理时间/状态/重复输入，用户解决歧义并确认变更。解析时间必须关联通知日期/时区；没有依据不能猜“周五”或到期时刻。提取与通知送达是不同可靠性问题。

普通截图转待办已被Todoist/SnapDo覆盖，Ohai/CoFamy也有事项/资料/清单流程。因此未证明此候选有独有性。待对照的具体问题仅是“同一事项多来源+变化+准备材料，是否比已有方法更少整理/遗漏”。如果现成App同样完成，改为模板/扩展或停止，不硬说生活场景是新赛道。

## 5. 候选B：个人知识应用练习App

### 用户与场景

要在近期理解并使用一份资料中的知识，已有课件、文章或工作培训材料，但不想手工制作练习的成年人。目标不是替用户完成作业或无限囤积资料，而是能解释/选择/应用自己需要的内容。

### 产品

选一个学习目标与小段材料 -> 短解释 -> 用户主动回答或完成一个小应用题 -> 有原文依据的反馈 -> 针对具体错误再练 -> 后续复查。将“看过/自述懂了/模型判过/实际练习表现”分开，不给无依据掌握分。

可以覆盖学习材料与工作培训；生活技能只在资料适合与低风险范围使用，不做健康/法律等专业能力认证。

### MVP / 实现

一种知识类型、一份材料、一类练习和可追溯反馈；用模型生成与校核，规则控制题目与答案来源，必要人工审核评分尺度。客观题、开放题和实际技能任务不得混为同一“准确率”。不从零造间隔重复算法，不先生成全套课程/视频/语音老师。

NotebookLM、Brainy及其他学习App已提供生成卡片/测验、进度与复习。本候选“知识应用/迁移练习”只是待比较焦点，不是已确认的功能空白。必须看新情境任务和延迟复查，而不是生成题量、观看时长或模型自己的评分上涨。

## 6. 候选C：日常表达与沟通演练App

### 用户与场景

普通人即将做一次简短解释、提出请求、反馈不同意见或小组发言，希望先练习一次；不需要泛化为所有内向者、心理疾病群体或销售团队。

### 产品

用户说明情境、对象角色和表达目标 -> 进行短练习 -> 针对用户原话标出歧义、遗漏或未达目标处 -> 只重练相关一段，保留可带走的要点。反馈依据用户明确目标，不根据声音猜真实情绪、人格或对方一定怎么回应。

### MVP / 实现

一类普通场景，文本或录音选一条路线，几种通用对话反应，具体片段反馈与再练。模型生成角色反应和语义反馈；不仿冒具体真人、不录取未同意第三方语音、不默认长期开麦，不承诺真实沟通一定成功，也不提供诊断/治疗。

Yoodli已支持自定义情境、材料、反复训练和反馈，因此本候选的消费者场景/中文化不是足以成立的差异。实时语音延迟与费用必须实测；先不要把Voice API和复杂角色系统纳入开发。

## 7. 排序与创新边界

本轮推荐顺序是产品匹配度判断，不是量化市场评分：

A个人事项准备：最符合跨学习/生活/工作的实用功能目标，结果具体；强竞争、权限和提醒可靠性是主要风险。
B知识应用练习：学习与工作帮助直接，适合小范围检验；生成测验/复习已经很成熟。
C沟通演练：交互体验明确，也可覆盖多场景；通用模型/Yoodli替代及效果评测难度更高。

A只是优先研究候选；没有批准新产品名称/开发或证明剩余缺口。不要同时开发三种App，也不要把A+B+C合成一个万能助手。

不作为独立创新立项的功能：截图提取日期、自由话语拆待办、收藏加AI搜索、资料生成测验、无限角色聊天、简单跨端同步。它们可作组件，但本轮已有直接供给反证。

## 8. 可积累资产与技术边界

原P0的来源追溯、修改前后对照、明确Unknown可以作为内部经验；不强迫消费者理解版本/验收协议，不锁定PowerShell/Windows界面。已有代码不决定人群。

可积累的是授权、脱敏且人工校准的真实事项变化/误解析与纠正案例，或可验证练习/反馈案例。没有现成数据壁垒/网络效应，不聚合私人材料、不锁用户数据。界面好看或多一个按钮不证明更难替代。

目标用户不必自备API Key；产品提供方仍要解决合法模型接入、使用地区、费用/上限、隐私和失败回退，不能说个人订阅自动充当应用API。所有实际安装/新服务/模型调用/费用需下一步明确范围。

## 9. 下一步最小工作与衡量

不再先发一个八功能Codex大包。先比较A的一件真实低风险事项在“资料首次到达 -> 后续修订 -> 准备 -> 实际使用”中的步骤与结果，强基线包含普通日历/提醒+资料及Todoist/Ohai/CoFamy的合理能力，不故意只给基线一张图。

继续公开资料/有可见来源的任务研究，收集输入、变化、错误/恢复和结果；公开产品示例可用于能力审查，不能当真实用户失败。没有可用第一手材料就明确缺证据，不把用户个人项目顶上、不模拟访谈。

候选指标：正确字段/事项匹配、漏步骤/错日期/错误合并、未经确认的变更、人工纠正与准备用时、能否找到所需材料、提醒干扰和后续自愿复用。学习候选看保留/应用，沟通候选看明确目标与片段反馈；不以对话轮数/打卡替代收益。

这一轮只做方向和资料更新，不接触外部用户、不创建真实提醒、不操作邮箱/日历/相册、不安装运行竞品、不改源代码、不付费或发布。
