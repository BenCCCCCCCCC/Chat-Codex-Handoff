## 2. 产品定位与四层定义

用户/场景：成年人读过一份有限材料，近期需要用自己的话解释概念、条件或机制；希望知道这次讲解是否表达了要求、哪一句不清楚。首版普通话、单人短录音、概念/规则类；不从owner个人项目选市场，不等同于考试、所有社交技巧或职业能力测评。

产品：提供可回听的知识/逻辑反馈与独立的口头表达观察；让用户修正具体片段，而不是一个无法核对的总分。语音是有证据的练习记录，不只是替代键盘的输入按钮。真实需求频率、愿意录音、重复使用和付款未知。

完整v0.1：材料/目标、录音或主动上传、质量检查、转写/关键片段纠错、声学观察、逐条件反馈、原声联动、局部重录、尝试记录/导出/删除。MVP的限制在内容种类/时长/单端/低风险，不在于删掉错误处理或只做预置样例。

可实现层：浏览器录音/播放，已有VAD/ASR/对齐组件，规则化测量与引用校验，单一语义模型的隔离评审请求。无需训练基础大模型；声学语料校准、语义误判、隐私/成本和跨设备兼容仍需实际验证。优先自有轻Web入口，插件后置取决于合法原声权限与使用负担，不由品牌或旧WinForms决定。

## 3. 架构选择与替代方案

A 纯文本链：录音转文字后只让模型点评。最简单，可用于基线，但不足以支持基于真实停顿/重复/回听的承诺。
B 音频端到端大模型：整段音频+材料一次给音频模型。它可能利用韵律等信息，不能预设能力差；但时间定位、测量来源、分项复现与错误归因不应只依靠生成的自述。保留作后续公平对照，不作为首版唯一裁判。
C 专项口语评分服务：可提供其语言/任务范围内发音/流利度能力，但不等于中文概念理解或完整逻辑判断，也不是免费PTE评分复刻。
D **首选：双通道测量/识别＋分层LLM解释**。优点为证据可追溯、模块可替换、异常可局部重试；代价为时间对齐、接口与调度复杂，仍要测实际精度/延迟/成本。

首版录完分析，不实时逐句打断、不必生成语音回答。按需要对问题片段做用户回听或一次已授权专项复核，不默认多ASR投票/每句话多个模型。

## 4. 端到端处理图（设计，不是运行证据）

材料/目标 -> 确认本轮criteria与source版本
录音/上传 -> 原音频保存、哈希、解码与质量检查
  A：音频 -> 语音活动估计 -> 有声/非语音候选区间、时长等原始测量
  B：音频 -> 忠实ASR -> 原始转写、可用时间/可靠性信息 -> 必要对齐
A+B -> 同一原音频时间轴 -> 片段、文字、事件关联 -> 证据质量门禁
  C1：来源+criteria+可靠转写 -> 内容/逻辑评审（不输入声学流利度统计）
  C2：转写+声学/文本事件 -> 表达候选解释
综合：C1与C2经校验后 -> 排序/最多几个重点/回听/重讲，不互相覆盖

可用同一语义模型完成C1和C2的隔离请求；不是要求两个供应商/agent。隔离降低声学指标影响知识判断的风险，但不保证统计独立或消除转写中的风格线索。合并默认程序模板完成，确需自然语言综合时限制其只能引用既有发现，不能新增事实或重写数值。

如果为了首个接线原型合并一次模型请求，应标为早期简化版本，并测试风格偏差；不能说它已等价实现隔离设计。模块调用次数/价格与预算在执行前锁定，不写无限重试。

## 5. 检查器到底检查什么

“检查器”不等于全确定性，也不是从零训练语音引擎。VAD/ASR/分类器本身是统计模型；基于已估计区间的计时/计数才可以重复计算。输出要记录方法、版本、参数和不确定性。

### 声学侧

- 录音时长、解码问题、削波/极低音量候选；不把只有音量的粗筛当精确SNR。
- 估计的speech intervals与内部非语音区间；首尾等待单独记录，不混入句中停顿。
- 内部非语音区间的次数、时长、占比、分布及位置，记录阈值；指标应称“检测到的停顿/非语音候选”，不是心理犹豫次数。
- 区分用户主动暂停录制、设备中断/丢块和录音内部安静；无采样数据的空档不能当沉默。
- 单人首版不引入说话人识别、声纹、情绪/自信/智力诊断。

### 音频＋文本侧

- 中文初期以明确计数规则的汉字数/分钟描述速度；混合英文如何计数需版本化。不能把英文WPM或近似字数冒充音节率。
- 若展示总表达速度与排除检测停顿后的速度，两个分母须显式定义；不能因为去掉停顿数值变好就宣布学习进步。
- 填充词、重复和自我修正先定位候选，再看语境/原声；“就是”“然后”可能承担内容功能，“不、不对”可能是在成功纠正自己。
- 自动标点是ASR推断，不是原声真相。句边界/段边界是带来源的估计，不能用ASR逗号作为唯一正常停顿标准。
- 逻辑跳跃、事实错、必要前提遗漏、指代模糊属于语义层，需要转写/来源，不靠停顿阈值推导。

不设全球通用的“超过X秒就扣分”或“每分钟必须Y字”。工程阈值控制检出候选；教育评价锚点需另行人工校准。健康停顿/有意强调/语言差异/口吃不能自动成为知识缺陷。

### 本轮新增源码发现

Silero get_speech_timestamps源码含threshold、min_speech_duration_ms、min_silence_duration_ms、speech_pad_ms、秒级输出分辨率。默认逻辑会过滤短段、给区间补边且可舍入；为切段服务的默认值不能不经校准直接当口语评分参数。优先保留采样索引和参数，音频内容不剪去停顿、不时长压缩后再测；ASR分段若压缩/拼接必须保存回原时间映射。[N02]

WhisperX文档明确语言相关对齐、数字/符号可能无法对齐、重叠语音等限制。不把未对齐token插值成“已测精确时间”；回退到确有依据的较大片段并标精度不足，或暂不提供该发现的精确跳转。[N03]

## 6. 数据质量与转写纠错优先于责备用户

先检查文件可读、长度/格式界限、是否有足够语音。无语音/严重损坏不请求模型编造分析。音量不足或部分区间不可靠时允许部分报告，只阻断依赖不可靠区域的结论。

ASR尽量保留实际否定、条件、重复和自我修正；原始转写与可读排版视图分开，不能先润色再把润色稿当原话。术语提示只给必要词，不给完整正确答案诱发答案化转写。

关键否定、数值、术语或条件存在识别疑点时，用户可点回原声确认。没有ASR置信度不能伪造置信度，也不能声称所有关键错误都可自动发现；高置信也可能错。人工检查只是针对可疑点且有纠错入口，不默认每次校对全文。

纠错产生新transcript_revision；重新计算依赖文字的指标、对齐和语义发现，旧结果标过期但不覆盖。原声timing观察不因用户文字纠正而消失。改写答案是coaching_text，不是transcript修复；真正重录才产生新attempt。

## 7. 内容、逻辑、表达与进步分别定义

内容：按已确认标准标“已说明/部分说明/未在本次呈现/与来源冲突/待确认”，给引用。模型不得因为来源没有写到就把一个合理补充认作错误；有争议先指出依据不足。

逻辑：记录用户实际表达的主张、前提、因果/条件、例子和结论关系。每条关系需引用原话；模型预训练猜到的正确关系不能自动补成用户说过。接受合理的不同解释顺序，不以连接词计数代替逻辑。

表达：可测候选区间/重复/自修正和结合语境的建议，非PTE/人格/疾病诊断。没有声学异常也不代表“逻辑清楚”。

进步：同题有提示修正、相同要求的新独立尝试、新情境应用分开记录。文字编辑/模型换版/标准改变不可当口语或学习进步。长期学习收益/迁移/留存没有在本项目验证。

采用C1先盲于声学统计，是防止把“停顿很多”不当用为知识评分依据的工程选择；同样内容不同语速/停顿的对照须检验该选择是否生效，不称已证明无偏。

## 8. 综合解释与输出合同

输入是结构化证据包，不是“流利度60分＋一段文本”这样的有偏摘要。至少含：session_id/attempt_id、audio_id/hash/duration/timebase、source/criteria版本、transcript_revision与片段ID、事件起止/方法/参数/可靠性或null、被阻断的范围、帮助水平。

结果字段建议：finding_id、dimension、criterion_ref（适用时）、source_refs、transcript_span_refs、event_refs、observation_or_interpretation、claim、reason、suggested_action、uncertainty、status。

数值和回放位置由程序据event/span生成。模型可以引用事件ID，不能重新算数、发明“停顿2.7秒”、替换音频ID或跨尝试复用旧发现。程序校验ID存在、时间在范围内、依赖版本正确、所引文本能对应；这些检查不能证明所有语义推断正确。

综合可以说：这里检测到一处停顿，同时前后缺少原因连接，请补充关系。不能说：你因为不会这个知识所以停顿。因果归因不明应写未确认并追问，而非错误归因给用户。

质检门禁应同时约束正向与负向结论：不可靠转写不仅不能扣分，也不能作为确定已掌握的证据。模型结构格式无效/引用坏/请求失败应重试受限或部分交付，不返回默认漂亮高分。

## 9. v0.1完整功能清单与主要页面

U01 材料与练习目标：正文/Markdown/少量预置原创材料，选一个说明目标，确认3–6条源锚点。暂不做任意扫描PDF/全学科知识图谱。
U02 录音或主动上传：单人普通话，建议60–180秒（范围非评分标准），格式/大小/权限检查，录音中断可恢复已保存片段；主动暂停状态可见。
U03 原声与转写审阅：时间线/片段回听、有限纠错，保留所有版本，明确哪些片段未可靠对齐。
U04 内置观察器：质量/语音活动/时间/速度/候选重复与自修正，显示事实来源，不生成心理犹豫诊断。
U05 语义评审：内容与逻辑独立于声学统计，来源引用与允许的替代解释，明确未评估。
U06 综合反馈与结构查看：默认最多三项优先反馈；点击跳原声/原文；“你实际说出的关系”视图通过同次语义输出实现，不单建图谱数据库。
U07 定向重讲与比较：保留第一次，选择一个薄弱点重录，按同标准比较；可提出一个新应用问题，其学习效度单独待测。
U08 练习历史、导出、删除和失败恢复：关闭/重开能找到已保存数据；实际删除原声及关联索引；报告导出说明是否含音频；网络失败保留录音，不重复扣费重跑全部。

四个主要页面足够：练习设置；录音；反馈工作台（播放器/转写/内容/表达切换）；历史与数据设置。正常流程不要求理解JSON/SHA/模型Key。没有配置语义服务时，只能明确显示本地观察已完成/语义未运行；不得把fixture反馈冒充真实分析。

## 10. 推荐研发结构，不建设一堆微服务

一个响应式Web前端：TypeScript/React作为候选，MediaRecorder负责用户明确启动的录音，原生audio或WaveSurfer Regions负责回听。[N04,N05]
一个模块化服务端/任务worker：Python生态候选用于音频解码/VAD/对齐，语义API通过一个薄adapter调用；应用metadata可用SQLite，音频blob存独立受控文件/对象存储。实际已有环境与权限要由后续Codex预检，不宣称已安装。
逻辑模块：capture/storage、quality、transcribe、align、observe、assess、validate/report。模块边界不要求不同进程、不同供应商或多Agent；短录音不需要Kafka、向量库、分布式队列。worker可先和应用同部署，避免CPU处理阻塞UI请求。

ProviderAdapter需明确capability flags：支持语言、时间粒度、logprobs、保留填充词提示、是否可能自动清理、文件/时长限制、region/retention/billing。每次运行记实际model/version/config。适配是隔离变化，不同时上线多模型平台。

原文件保留；可派生单声道/目标采样率副本，记录映射。不在测量前删静音/伸缩时间或把强降噪后的波形当未变原声。捕获时设备/浏览器可能处理音频，应记录可得到的设置，不能保证真正未经处理的麦克风物理信号。

本轮重新读取的官方file transcription文档已经推荐gpt-transcribe，并列出prompt/keywords/languages。旧v2的推荐模型候选清单不能当最新选型。当前文档仍将timestamp_granularities限定为whisper-1；推荐转写模型不是自动具备全部时间能力。可选官方ASR+独立对齐/观测；实际中文关键语义、填充词、延迟与成本决定最终选择，不能仅按名字定最优。[N01]

首版不默认调用大音频模型点评每个片段。对齐/识别不能可靠支持的指标先明确降级，是否增加第二ASR/音频复核要有误差证据和预算，不为了完整表格堆模型。

## 11. 工程事实必须先固定的数据对象

PracticeTask：source_version、rubric_version、criteria与引用、mode/辅助规则。
Attempt：audio原件与派生件、采样时间轴、录制事件、环境元数据、consent/retention。
TranscriptRevision：raw/corrected/view类型、span IDs、对齐版本、来源与不确定字段。
ObservationSet：audio hash、detector/version/config、raw intervals/derived stats、有效范围；结果并不等于心理事实。
Assessment：model/prompt/schema版本、输入refs、C1/C2独立输出、被阻断项/报告版本、耗时与已知usage。
Repair：parent_attempt/finding refs、实际新音频，不覆盖原attempt。

事件与报告均必须绑定同一次attempt和版本，缓存键包括这些身份而不只看文件名。按阶段检查点恢复，避免网络失败后重复转写/重复付费；idempotency、取消和错误要有明确状态。

## 12. 成本与隐私，不推给最终消费者

用户主动录自己的声音/选择材料；录音权限显式提示，停止后释放mic，无后台听音或读取ChatGPT私有语音文件。单人、成人、非医疗/法律/财务高风险学习内容优先；不使用真实第三方会议默认做样本。

使用官方API/本地模型都需有效授权。API key服务端存储；不可由个人订阅/cookie/客户端文件充当公共后端；终端用户不必配置Key。个人数据不默认为训练/跨用户知识库，日志默认只含必要技术ID，源正文/录音不写入普通诊断日志。

删除包括音频、派生件、数据库引用和搜索/缓存；备份与外部服务保留差异要说明，不声称一键立即删除所有第三方备份。云处理内容/地区/保留策略需按实际provider确认，未确认不开始采集。

每次有效反馈成本：ASR费用＋语义调用＋需要的对齐/VAD计算＋存储/流量＋失败重试。延迟近似为max(声学,ASR)+需要的对齐+C1/C2+呈现；若阶段依赖不能并行则如实记录。无实测不承诺固定秒数或免费无限。

## 13. 不另起泛调研，内部研发与集中验收怎样推进

产品规格到此足够开始编制有界工程任务，不再每轮改名称或追加无关功能。仍处产品/技术验证阶段，不跳到完整商业开发。

工程批次建议（同一范围、不是每批都请owner验小控件）：
A 数据与录音骨架：保存/解码/时间轴/导出删除、可测试的合同和失败状态。
B 双通道接线：实际可用的VAD/ASR/对齐；若模型/依赖/权限未获准，保留未运行状态而非造结果。
C 语义与证据校验：C1/C2权限、引用/版本/数值、异常/重试。
D 前端整合：完整新任务录音->反馈回听->纠错/重讲->保存/重开与错误恢复。

每个可执行Codex工作包必须先确定允许目录、source base、已有依赖、来源/声音许可、官方服务与最大预算；研究授权不自动涵盖这些实际副作用。本轮尚未发起本地预检，也没有默许安装或费用。需要费用/权限时一次汇总必要选择，不反复问文案/按钮。

### 不能后置的可靠性验证

- 无语音/噪声/截断/设备暂停不变成知识缺陷。
- 清楚但有停顿与清楚流畅内容应得到等价知识判断；数据是对照设计，不是已收集语料。
- 流畅而错误不能因声学好被判正确；ASR关键否定/条件错不直接归咎用户。
- 对齐、剪切/分块回原时间、引用存在/范围、旧版引用失效。
- 自修正能保留前后关系；有效填充词不全当坏习惯；合理替代表达不强制按唯一答案顺序。
- 模型结构化输出/引用校验不等于判断效度；人工校准主要负面发现，报告可判断覆盖率，不能靠全答Unknown得到低错误率。
- 纠正文稿不提升原音频指标；有提示重讲不混为无提示掌握；相同标准版本才比较。

人工样本与模型实跑需许可，不把TTS或脚本fixture称为真实用户。标注/主要负面发现由不同于生成器的人工依据校准；同一模型自评不是独立证据。开发内测验证系统是否可靠，之后的真实学习收益/留存/付费是另一阶段。[N08]

## 14. Chat替代性与竞争保持诚实

普通Chat＋好提示可完成口头解释的语义点评。本产品增量是主动拥有的录音时间证据、质量门禁、分层观察、可回听引用、可恢复/可修正的工程体验；这套能力也可以通过有工具的Skill/插件提供。软件集成复杂不等于市场需求、算法创新或护城河。

v2已读Vocenda、LaoshiAI、Yoodli和mattdiep15/feynman，直接同类结论保留；不重跑营销榜单。feynman实际评估接口文本+概念->结构化评审是可借鉴模式，不证明停顿工具能准确测知识或模型权重有效。原生Chat不被描述成只能写字。

本版不把ChatGPT Voice作为核心依赖，也不推测插件可获得宿主原音频。未来官方组件若可合法低负担承载同能力，可使用该形态。当前推荐Web是架构选择，不是已验证更受欢迎的入口。

后续对照：同来源普通Chat/学习提示；同合法音频工具的Skill；文本单通道；本双通道产品；如果实际必要，可比较直接音频模型。比较材料、提示辅助、输入时点与成本一致，不故意削弱对手。若音频通道只是增加噪声/成本而不带来可用反馈，保留可用组件并缩减，而不是继续堆功能。
