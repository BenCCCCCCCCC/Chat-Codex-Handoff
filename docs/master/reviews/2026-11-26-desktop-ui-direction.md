# V1 本机工作台 · 设计减法与验收

2026-11-26｜适用最近本地候选及后续 UI 批次。此次依据 [PR #45](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/pull/45) 已读提交 `4d0161926eb18ca1dd9782cd2f87dd0c2ecb839f` 的 HTML、样式和关键状态更新，结合 A/B 的既有截图审查。#45 已报告当前重点跳转、普通旧题提示和窄屏固定主动作；不重复领取。此处是可执行的体验方向，不是已运行或已改界面。开工以最新合并产品头为准，不抢 #45 实施分支。

## 设计判断：像一张学习桌，不像一个卡片面板

**一条安静的内容主区，一处稳定的动作区，证据随需要出现。** 学习者的材料、表达和题目是视觉主角。差异来自“反馈能回到具体原句，修完能再做”，不是 AI 图标、渐变、标签或更多组件。保留代码的模块化，取消“一个模块等于一张可见卡片”的映射。用对齐、间距、字重和细分隔传达关系，只有真正独立的对话框、输入控件、需关注的异常或首次体验示例才值得独立表面；不堆同权重描边、圆角、阴影和 badge。

- **Apple 官网**只作为介绍页/首次体验的参考：少量鲜明卖点、视觉节奏、克制留白。回访直接看到“继续”及接续位置，不再重复主张与介绍卡。默认工作区不放营销大字。
- **ChatGPT Desktop**参考桌面交互结构而不是视觉皮肤：少量稳定全局导航、可收起的主题/历史区、正文占主位、输入工具就近聚合、按需查看辅助内容。[官方桌面页](https://chatgpt.com/download/)与[新版导航说明](https://help.openai.com/en/articles/20001276-moving-to-the-new-chatgpt-desktop-app)是参考，不照搬商标、聊天气泡、模式数量或配色。讲解、引用与独立作答仍是本产品自己的交互。
- **HCI 与视觉依据**：[Nielsen 启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)的状态可见、识别优于回忆及极简设计；[渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)适合不常用选项，不隐藏主任务；[Palmer 的共同区域研究](https://pubmed.ncbi.nlm.nih.gov/1516361/)说明强边界会形成感知分组，据此用边界表达真正需要分开的内容；[Fluent 2 排版](https://fluent2.microsoft.design/typography)、[布局](https://fluent2.microsoft.design/layout)、[内容设计](https://fluent2.microsoft.design/content-design/)用来建立正文、辅助信息、控件的层级。优先 Windows 系统字体及中文回退、可扫读的行宽、左对齐、足够中性色对比。先做减法，不锁定像素或照抄品牌。

### 文案按动作删，不按字数删

1. 首屏只回答“在做什么／下一步是什么”。删口号重复、栏目自述、相同的标题+标签+说明，以及按钮文字已表达的内容。标题不使用“助力高效”“开启全新体验”；动词先行，例如「重讲这一点」「继续上一题」。
2. 一个事实只在一个位置说一次。文字输入区可用「文字讲解」作标题，保存后只显示「已保存在本机」；到真实发送前再提醒「将把选段和已确认文字发给 AI」，不要把两步都写成“开始后将发送”。本地保存、讨论发送选段、诊断发送选段和确认文字是不同动作，提示随实际动作而变；录音转写的上传提示同理。必要风险不折进纯帮助。
3. 反馈例：「漏了 18:00 的签到截止」→「查看原句」→「重讲这一点」。不堆「当前学习重点／反馈建议／下一步」三层标签。题目状态写「条件未核对，暂不判定」，不加虚构分数；对失败用「保存失败。重试或导出」，并明确会丢失时的后果。
4. 功能不拆没，文字/按钮按发生时机重排：证据、版本、备份、删除、费用、数据去向和不可逆结果都保留可发现的入口。文字和语义标签留在无障碍树，不能为了视觉简洁而让图标独自承载意思。

## 按一条路径验收

- 用相同合成材料和同一阶段做桌面约 1280px、窄窗 390px 前后对照：导入→开始讲解→打开原句→返回同一缺口→局部重讲；再确认一次回访落点。设计评审可记录首个正确动作、需要滚动/往返次数、是否理解保存与发送差异，不机械追求组件或字数少。
- 全流程只在当前任务区有一个明确主动作（可另外保留正常次级入口），主按钮/输入区域不挡正文或键盘焦点。走查 Tab 顺序、面板关闭后的焦点恢复、窄窗换行协作；用 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 的文本对比、重排、焦点可见/不被遮住、状态信息标准作为检查项，不宣称本轮做了完整合规审核。
- 先提交这一条真实可用的界面切片，再扩展档案视觉。保留旧证据及合成/真实分界。纯文案/低风险样式只做受影响实页对照，不重复运行整套回归；改变导航和恢复时只核对受影响路径。先验功能和阅读节奏，再谈风格完成。
