## 1. 目标与当前缺口

**用户**：拿一段课件或笔记自主复习、有一个具体概念还讲不清的学习者。**承诺**：用自己的话讲一遍，知道哪一点为什么值得修正，修完能换个情境自己做一次，下次打开知道该从哪里继续。保持个人学习、Windows 本机使用、可独立展示三个边界。

[#30–41 已实现的基础](CURRENT_STATE.md)包括多材料、条件核对、讲解/转写确认、诊断、补学/重讲、独立作答证据、题目复核、续学、材料版本与备份；#42 是已封存的转写研究。现有能力不重造。按仓库及已报告验证看，**风险不是缺更多入口，而是学习者能否不靠指导走通、何时算完成、下次是否走回同一个问题，以及反馈/题目是否足以支撑下一步**。这些要用入口实际走查核实，不把规划当缺陷复现。

## 2. 单一学习主线

1. **选材料和目标**：开始页优先短材料/既有选段；明确本次要讲清什么、将使用哪几份材料。第一次入口保留现有免 Key 示例，明确示例为预编写、不写入真实记录。正式学习打开已选材料；可先跳过聊天。
2. **先讲再核对**：同一主动作进入语音或文字讲解。语音必须提示核对数字、否定和术语，文字可直接讲；仅在用户明确确认后使用该文字版本生成诊断。没 Key/权限被拒/转写中断时保留原声或文字草稿，给文字入口；不能提供真实分析时直说，不冒充评分。
3. **先处理一个问题**：首屏列出一个优先缺口及理由，展开即可核对原文和讲解原话（遗漏没有原话就标未表达）。仅以明确目标、材料适用条件和实际回答判定。前提不明，给“确认依据/暂缓本项”，不算错；当前目标未见缺口，显示“本次已表达”，可选做新情境题，不硬造改进点。
4. **补学→重讲→应用**：复用原报告导出的补学/局部重讲和独立情境练习。补学后提供回到同一问题重讲的入口；主动开始新一轮重讲才形成新的讲解版本；仅更正转写或承接旧表达不算新的独立作答。旧诊断只读。练习优先给一个改变情境而非替换措辞的题，先交回答才展示判断。保留“题目有疑问”、条件冲突和答案不足的暂缓机制。有限本机规则不覆盖时，不假装会出题，不隐式调用模型；可继续重讲或显式走现有开放练习。
5. **结案与继续**：首选同一个活动卡片/主按钮，从现有记录得到“讲解待确认 / 待核对反馈 / 待重讲 / 待作答 / 继续修正 / 本轮已完成”。已完成项显示所选目标、修正点、练习证据和下一步。若未练习、尚待复核或只有草稿，只标已完成的环节；不得用“已掌握”。主动先停可以从当时环节继续。过期和备份沿用现有政策并显示提示，不承诺过期自动找回。

**贯穿规则**：优先沿用现有状态和关系：材料快照及版本 → 当时选择与条件 → 讲解/确认文字与报告 → 反馈目标 → 问题版本、作答和判断。阶段可以从这些证据推导，不维护第二套可能矛盾的进度真相；若确有跨版本关联缺口，最小增量、评估备份向后读取，旧记录未知不补造。新增报告可采用已有的状态组，不把材料引用存在当作解释正确、把用户选择当事实、把没点应用内提示当作独立证明，也不把未录到的内容判缺漏。题目答案/示范不先于首次作答呈现；允许查看来源时，仍区别“练习”与“无辅助的证据”。同一请求按已有去重与明确重试；刷新、搜索、恢复和查看不得隐式发真实请求。

## 4. 固定验证任务

- **常规回环**（合成）：门禁材料“须已实名并在 18:00 前签到”；首次讲解仅提到实名；诊断引用条件，不给遗漏伪造原话；补学并确认新的完整讲解。新情境：小王已实名但 18:05 才签到，先让学习者说明结果及理由，再显示反馈。核对首轮证据、改后讲解和新题回答分别留存。可用现有受控同类案例和模拟输出。
- **反向边界**：两条材料给不同制度，题面没指定使用哪条。可判适用范围，不能给学生判错该项；在草稿未交或题目未复核时退出再恢复，保留现场。若采用新版本/明确条件，旧结论不跟着重算。
- **最小发布检查**：免 Key 示例与正式路径清楚分开；正式路径做上面主流程和反例；核对一次 v5 备份恢复后能找回准确目标、题目与历史版本，旧备份复用现有兼容验证。遵循 [TESTING](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/blob/d1d662d2376b5618b03fadff214d4680ebf86e57/docs/TESTING.md)，仅为改动及关键用户结果补校验，不针对文案跑全套回归。报告分开写“离线工程”“本机真实入口”“模型质量”“学习效果”，不混报。
- **后续研究，不挡工程**：同材料、同时间对照常规来源型助手；两组用相同量尺，不把答案提前给一边。24–48 小时换情境、不看提示/材料后作答，分别评概念、应用与解释；小样本只用来校验可行性。质评优先抓无证据判错、暂缓错判、错误引用和重讲后无法迁移。现有[同输入协议](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/blob/d1d662d2376b5618b03fadff214d4680ebf86e57/docs/research/quality-baseline-2026-11-18/PROTOCOL.md)继续作为诊断质量基线；真实调用/人类参与者需要各自授权。竞品参考：[Google 已公开的练习功能](https://blog.google/innovation-and-ai/products/gemini-notebook/three-tips-study-gemini-notebook/)。
