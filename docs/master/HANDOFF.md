# 知而能讲 · Codex 工作交接

把「知而能讲」完善成学生愿意日常使用的 Windows 本地学习产品。学生能带自己的课件，用语音或文字讲清一个概念，从原文和自己的表达中看懂问题，重新解释或尝试新情境，下次回来能接着学。作品集访客能免密钥体验这套过程。

## 怎么推进

结合[当前状态](CURRENT_STATE.md)、实际代码和用户体验，优先解决最妨碍学习的问题，连续完成有意义的改进。你可以调整优先级、合并工作、重构架构或采用更合适的方案。可逆的设计和工程取舍自行决定，已有授权涵盖实现、自审、修复、提交、PR 和合并。需要产品负责人决定的事项集中提出，同时推进其他工作。

验证做到足以判断改动是否有效。优先复用已有证据和 CI；发生新改动、出现失败或仍有具体疑点时，再扩大检查。比如改文案可以直接审差异，修草稿丢失可以走一遍此前丢稿的操作，改存储或计费则检查实际受影响的旧记录或重复提交。是否新增测试、用什么环境及何时做整体验证，由你根据影响决定。实现也按实际需要保持简单。

交接时简要写清用户现在能做什么、依据是什么、还剩什么。常规进展可以合并汇报；形成阶段结论时再同步 MASTER。

## 本轮交付与续接（2026-11-17）

[PR #30](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/pull/30) 与 [PR #31](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/pull/31) 已合并，产品基线为 `ce5566a`。学生现在可恢复新建草稿、保留自定标题、撤销材料替换；无密钥也可保存材料并在本地继续。导入选段保留文件页／幻灯片位置，反馈可定位原文再回到同一卡片，修改材料保留旧主题与来源。完整 CI、本机启动及窄屏核对依据见[当前状态](CURRENT_STATE.md)。

下一步优先完善练习到准确历史反馈的持久返回定位，再接入键入讲解与同一缺口的重讲对照。现有练习目标标识仍主要依赖讲解／转写版本及条目序号，同一版本有多份报告时需明确归属；新报告身份与旧记录兼容方案可自主确定。材料集、媒体分离存储、转写迁移等尚未实施，按实际价值排序，不必把路线拆成固定流水线。

新建草稿暂不在主题备份内；原文件仅保留选段与位置元数据；编辑正文会清除失效页码。七天保留、旧备份兼容和费用边界维持原约定。本轮无新增产品决策待办，也没有使用真实模型 API 或恢复已拒绝的实验候选。

## 产品路线

| 方向 | 用户应得到的结果 |
|---|---|
| A · 工作台与上手 | 能顺利开始或继续学习。草稿和自定标题能保住；缺少配置时，有清楚且当下可行的操作。桌面、窄屏和键盘使用都顺手。 |
| B · 材料与记录 | 从反馈能回到准确的材料页和版本。修改课件后仍能理解旧反馈，历史记录和已有备份可继续使用。 |
| C · 讲解与转写 | 支持录音、上传或键入。切去看课件后可以继续利用已录内容。转写服务迁移后，校对、旧录音回听和费用记录仍然可靠。 |
| D · 反馈与练习 | 学生看得懂优先补哪一点，能就地重讲、对照前后表达或独立做题。无依据的题可质疑和修正，合理质疑不会被记成学生答错。 |
| E · 多来源与复习 | 多份材料有分歧时，能追溯依据、裁决影响当前判断的冲突。回访时找得到上次卡点和后来独立应用的证据。 |
| F · 本地交付与作品展示 | Windows 用户能启动、恢复和备份；访客能看到真实的设计取舍。工程检查随改动影响而调整。 |

以上是产品目标。桌面丢稿和导入覆盖已有直接复现记录，适合作为起点；若当前代码或实际使用揭示更高优先级的问题，可直接调整顺序。按需查阅[详细审查、技术调研与设计备选](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/blob/bc2dffe4da05ecc1bb23499f452a0bd51b580768/docs/master/HANDOFF.md)。其中的分批顺序、指定文件和验收场景供参考。

## 谁决定什么

已确认的个人学习与作品展示定位、用户数据权限及费用边界继续有效。新增付费调用、个人录音研究、变更七天保留政策、大规模用户数据迁移、公开部署，或扩大产品范围时，由产品负责人决定。原有实验额度已结束。
