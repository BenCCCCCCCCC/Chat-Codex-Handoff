# 知而能讲 · 完整产品路线与 Codex 执行计划

2026-11-17 · MASTER 产品规划 · Windows 本地个人学习与作品展示

## 目标与执行入口

学生能带自己的课程材料来，用语音或文字讲一次，看到最值得讲清的一点和判定依据，重新解释或在新情境作答，下次打开还能从这个点继续。面向个人自学和课程复习，优先支持中文材料、夹英文术语、带页码的真实课件。作品集访客可以免密钥理解产品价值与局限。

产品基线是 `prototype/study-teachback-v0.1` 的 `8634919`（PR #28）。最新进度读本分支 [CURRENT_STATE](CURRENT_STATE.md)。首次执行先 fetch 两个分支，看已合并与进行中的工作，接下面第一项未完成的交付。实现和合并在产品分支体系完成，两个 MASTER 文件只维护计划、事实与交接。历史参考见[10 月完整交接](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/blob/3410de4fc40e8504bfeb9046cacbedc23eff3b34/docs/master/HANDOFF.md)。

**给 Codex 的任务：** 承接本文件的 A–F 批次，按依赖实施、检查、修复、自审、提交并推进下一项。在同一轮内合并能一起完成的工作。真实支出、改变数据保留政策、对外部署或超出个人学习定位的决策只挂起受影响的工作。无需用户搬运任务包、挑实现细节或逐项签收。交接时写下精确到可继续操作的下一步。

## 界面和交互目标

| 学生所处的位置 | 屏上最重要的内容 | 主要行动与恢复 |
|---|---|---|
| 首次打开／再次打开 | 初次给「用自己的材料」「体验示例」；回访优先显示上次的具体学习目标与草稿。服务状态在需要时解释。 | 开始或继续学习。尚未配置 AI 时可看示例、整理材料、打开先前结果。 |
| 选课件与本次目标 | 桌面左侧目录／来源，右侧显示选中段；窄屏以可返回原位置的来源面板替代双栏。 | 采用本次选段。已填材料可保全或撤销替换；扫描页、空材料和过长材料各有可做的下一步。 |
| 学习与表达 | 材料问答保持可用，已经预习过的人可直接讲；录音、上传和键入在同一表达入口选择。 | 当前方式只有一个主操作，录音时显示进度及切走的后果。校对文字时可跳到相应原声。 |
| 反馈与纠正 | 默认呈现优先问题、依据、可执行的下一步；其余已讲对项折叠。材料不足或仅未提及时用准确措辞。 | 优先局部重讲或适用的新题；完成后回原问题并比较两次表达。资料引用应定位实际页／原句。 |
| 练习、疑问与复习 | 学生先独立作答，再看判断与来源。题有疑问时显示争议前提和修订入口，旧判定有明显状态。 | 继续作答、按修订题重答或回学习目标。历史卡片显示最近证据、待办和到期日。 |

保留可读的蓝白视觉、原生控件、焦点样式、减弱动画和状态播报。优先统一标题层级、状态词、主次按钮、移动端布局；成功、处理中、受阻、可恢复分别给出下一步。视口变窄或浏览器放大后，来源和返回路径仍能通过键盘操作；异步完成后焦点落到新内容或原触发器。提交前取当前桌面与窄屏的代表页面做视觉复核，不为每个文案建立快照。

## A–F 执行批次

### A · 启动、材料草稿与导航　优先 P0，可直接开始

- 改 `launch.ps1`、`server.mjs`、`ingestion.mjs`／`extract_source.py` 和新建／工作台视图。区分本机启动、文本导入、PDF 提取、模型和录音能力；按功能提示配置。TXT/MD 应有不依赖 PDF 库的读取路径，离线示例、粘贴和历史可用。启动器使用稳定的应用身份与接口版本识别服务。
- 新建页草稿含正文、标题和学习目标；重进当前导航保留编辑。短文档在空白页自动使用；有内容时给预览、明确替换和撤销。保留已有的长文选段。
- 收敛全局底栏与阶段操作。站在学生角度处理空白、未配置、等待、可重试和已保存状态。逐步提取负责导航／状态和来源面板的代码，不一次重写页面。
- **一次交付验收**：Windows 正常入口无 key 打开示例与既有记录；有草稿时查看示例、回来、导入并撤销，原文与标题保持；窄屏能完成同一条旅程。

### B · 材料、版本与存储　优先 P0，与 A 的界面工作可并行

- 在现有来源和讲解模型上补稳定材料 ID、修订号、片段 ID/页号、可编辑角色和学习目标。整份材料属于主题，每次发送的是用户选段和必要上下文。修订只使依赖该版本的结果过时，历史引用保留原快照。旧版单来源映射为一个来源。
- 同时确定讲解、诊断报告与题版的标识。两个报告即使绑定同一份确认文字也分别保留。跨页面恢复指向当时的目标、报告和题，不靠列表序号定位。
- 从 `storage.mjs`、`backup.mjs`、`record-search.mjs` 演进主题摘要索引、分离媒体与元数据、按需加载。支持旧 v1 备份与中断后恢复；保留当前七天行为并显示实际到期日。有并发编辑时保留用户内容或提示冲突，禁止静默覆盖。
- **一次交付验收**：导入一份多页课件，从反馈定位具体页；恢复含旧语音的 v1 备份，改材料后旧报告仍引用旧版；列表展示无需读取所有音频。使用同一份样例贯穿。

### C · 文字／语音教回与服务迁移　优先 P0，依赖 B 的标识约定

- 支持直接键入讲解，也可录音或上传。文字讲解跳过 ASR；历史显示输入来源与参考材料情况。录音被打断时保留可用部分，让学生试听、使用、续讲或舍弃；设备错误有明确退路。让学生知道哪一步才将音频发往模型。
- 将模型能力、响应格式、时间定位精度和费率配置与产品功能分开。复用 `audio-input.mjs`、`voice-review.mjs`、`transcript-playback.mjs`、`provider.mjs` 与 `ledger.mjs`。当前 `normalizeASR` 需要 segments；支持仅有全文、整段回放，以及真实的段／词时间。历史 Whisper 锚点继续可读；没有可靠时间时显示整段回听或文字。
- 为一次用户提交保存操作 ID 与状态，能复用已收到的结果、区分保存失败与网络结果未知。只在可能重复计费的重试处说明；本机材料处理不再被无关模型请求阻塞。保留预算预留、已知支出与未结算状态。
- **一次交付验收**：同一目标分别键入和用合成音频完成教回；另以一份历史词时间记录和一份新格式记录核对正确降级。在真实 Windows 做录音切页／设备中断的代表流程。新模型正式替换前，用一次经批准的真实对照验证中文术语、数字、遗漏、定位、延迟与费用。等待预算时可完成适配和其他批次。

### D · 证据诊断、重讲和公平判题　优先 P0，承接 B、C 接口

- 复用 `diagnostic-localization.mjs`、`practice.mjs`、`understanding-task.mjs` 和现有题目争议状态。每轮区分有依据的错误、本次尚未提到、证据不足及自我纠正。按前置依赖、错误严重性、目标与来源给出一个优先项；同时保留其他可核对发现。
- 反馈、局部重讲、新情境题和回顾共享明确的返回目标与滚动／焦点位置。呈现「初讲怎么说、反馈指出什么、重讲改了哪里」。有提示重讲与独立应用分别记录。当前目标没有合适题时，直接提供重讲或再学。
- 题目与依据版本化，保存适用条件、所需来源、可接受的等义回答及不可判条件。先判题能否成立，再判回答。可以标疑、看依据、修改或退役题目、按新版本作答；不把旧错判记作用户失误，不覆盖历史。离线规则保留为能确定的小部分，扩展真实课程覆盖靠有效题与可审查标准。
- **一次交付验收**：用已有无依据资金题和一组未参与调试的有效题，从标疑走到修订与重新作答；能解释合理质疑、猜测、意思相同但措辞不同分别如何处理。完成一次「发现缺口→重讲／新题→回原处」的桌面或窄屏旅程。上一轮被拒绝的候选保留为对照。

### E · 多来源学习、冲突与复习　优先 P1，依赖 B、D

- 实现个人材料集的来源选择、角色建议与更改、引证和裁决记录。以 [Issue #3](https://github.com/BenCCCCCCCCC/Chat-Codex-Handoff/issues/3) 合并已有研究，先用同输入对照定准规则，再接入正式诊断。2–4 份是受控样本规模。可确定的学习内容继续处理，相关冲突只暂停受影响的结论；无关冲突可见且不打断。
- 首屏和记录页按具体目标显示最近的初讲、重讲、独立新题、疑问题与下一次可继续处。搜索定位到正确版本和页码。以一次实际行为表达进度，跨周到期可导出；长期保存或改变删除默认值属于单列的用户决定。
- **一次交付验收**：同一课件与补充笔记出现一处影响判断的分歧和一处无关分歧，裁决后能继续学习；恢复后能回到对应原文、初讲和最近表现。

### F · 日常使用、作品集与交付工程　贯穿实施，最后集成

- 更新免 key 示例为两种不同能力：一个正常纠错与重讲，一个材料不足、题应暂停的实例。让访客看见学生原话、依据与产品处理，用清楚标签区分预写示例、模拟数据和真实体验。整理 Windows 安装／启动／停止／更新与备份说明，从干净目录完成一次上手。
- 状态提示统一为学生能执行的动作，设置内集中解释数据位置、保留与导出、费用和可用服务。复用可访问控件，在键盘、窄屏、常规桌面和放大场景抽查主要旅程。
- 调整 `.github/workflows/offline-tests.yml` 的实际路由。文档和轻量样式以差异或一次视觉复核为主；提取器变化才安装相应依赖，真正依赖提取的集成路径一并安装；单模块走现有定向检查。跨模块合并／候选发布版集中做一次 Windows/Edge 主流程；同一提交复用 CI 结果。故障修复仅在现有检查会漏掉真实回归时补例。
- **交付标准**：可从干净 Windows 启动，能完成一轮带来源的学习、一次纠错、一次离开后继续，旧记录可读，演示无需密钥。个人学习者试用时记录能否独立完成、卡点和新情境表现。技术验收、诊断质量、学习效果分别说明。发布对象为可交付的本地版本；公网部署另作决定。

## 底层架构的取舍

沿用 Windows 本地工作台、Node 服务、原生网页和 IndexedDB。现在不需要更换前端框架才能解决上述失误。将已经影响用户的职责分开，随业务批次改动。当可编辑来源增加时，先用现有提取区块、原文与选段索引；只在正常课程规模的材料确实找不准、找不全或太慢时引入更重的检索服务。

| 现状与决定 | 改造后的契约 |
|---|---|
| 多处 UI 通过隐藏 DOM 与清空 current 控制阶段 | 每个可恢复位置有 view、topic、目标和适用的讲解／报告／题版，控制器统一处理返回与恢复；输入草稿由所属视图保存。 |
| 转写格式决定能否进入内容诊断 | 内容诊断只要求有来源的确认文字。声音是可选证据，精度来自实际数据；用户修改转写后仍能回听原声。 |
| 报告、纠错、出题、判答容易共用一段建议 | 独立保存具体发现、下一步、题面、审题结果和回答判断。只为有明确收益的一步调用模型；已确认版本可复用，重新解释有新版本。 |
| 研究脚本与主应用同目录，当期模型和费率写入运行逻辑 | 保留历史脚本、费率和收据。产品按能力读取当前配置；每个新请求记录实际模型、配置版本、用途和请求结果；按所改功能移动必要边界。 |
| 长期学习只有主题记录、缺乏同一目标的连续证据 | 来源版本→一次表达→一项发现→一次重讲或练习→回访，均可追至原记录。以最近表现和资料依据呈现；声音节奏不作为知识正确性的判断。 |

## 发布顺序与 Codex 自主推进

| 顺序 | 可交付版本 | 启动与暂停条件 |
|---|---|---|
| 基础可用版 | A＋B。能进入、续写、导入、定位、保住历史。同步推进 F 的 CI 路由。 | 立即开始。A 与 B 可在同一批或互不冲突的工作分支推进；共同的来源、路由契约由一个实现维护。 |
| 完整学习版 | C＋D。语音／文字能到同一个有依据的结论，修正后能重新表达或应用。 | B 的标识定好即可并行。离线适配、界面和数据不等待新模型预算；实际对照与生产切换单列。 |
| 连续使用版 | E＋F。多资料、复习、历史恢复、双主题示例和 Windows 交付。 | 重用前两版的证据和导航。多源质量未达标时发布已有可靠功能、标注该路径状态；不让研究结果阻塞基础版本。 |

常规工作使用小而清晰的内部提交、按有意义的功能包合并 PR。每批复用已有 Issue／PR，确有独立追踪需要再新建。Codex 自行处理合并冲突、定向验证、可修复失败和文档同步。一个批次结束记录产品版本、可操作入口、实际验证、已知缺口与下批起点；有明确范围内缺陷直接修复。可并行读资料或做独立审查，不按代理数量组织开发。

**效果与产品验收。** 工程指标看能否启动、输入是否保全、恢复是否回对位置、一次操作是否重复发起调用。可用性看首次走到有效反馈的耗时、各步骤卡点、意外重录／重新找材料次数。AI 质量分开报告有题覆盖、有效题数、无依据误判、遗漏、优先项和正确弃权，保留真实分母及同输入有分歧的报告。学习价值看学习者能否在未见且无提示的情境再次正确解释；在下一次自然复习观察保持。对照使用同一份材料和解释、匿名评阅；成对比较时轮换条件，避免先看到答案污染下一组。有调试样本也有未见材料。人评与真人使用在候选版本上集中安排，由 Codex 准备任务、材料与记录表。工程 CI 不能替代它们。

**三类决策。** Must Fix 包括会丢学习内容、原文引用失配、无效题错误归责、误计判断或无提示重复费用等已观察的用户问题。User Decision Needed 只汇总具体取舍：新增真实调用须给出用途、调用数、模型、总额上限与重试政策；改变七天删除、利用个人录音或对外部署按实际需求决定。Future Optional 包括云账户／同步、图谱、实时语音与跨设备服务，出现真实需求和可核收益后再纳入。普通样式、代码组织、已约定路径和日常验证由 Codex 决定。

**本轮证据。** 2026-11-17 基于合并提交 8634919，在 Linux Chromium Headless 153 的 1440×900 和 390×844 走查新建、导入、缺配置、记录及免 key 示例。短文件覆盖正文和标题、点击当前导航清空草稿、无 key 先建记录后提示重试均在界面复现。窄屏未见横向溢出，示例反馈卡起点约在完整文档 920 px 处；前置说明与材料占据较多纵向空间。另经实际提取入口比较固定／不同 pypdf 版本的 TXT 行为。Windows 启动器与录音中断按源码审查；真实 Windows 设备、现场模型、新旧转写质量及真人学习表现未在本轮复验。产品代码基线仍为 PR #28。
