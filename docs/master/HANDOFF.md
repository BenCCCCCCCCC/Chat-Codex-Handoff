### 产品目标与竞争假设

目标用户：使用课件、笔记、自学材料学习复杂概念的大学生和自主学习者。核心场景：复习一节课、准备考试或面试、确认自己能否解释并应用所学。承诺：把知识讲出来，找到具体理解缺口，核对依据，通过新的独立任务确认是否解决。核心竞争假设是来源版本可追溯的理解诊断与连续学习，而非语音或聊天本身。未证明更准确或更有效。

外部核查（2026-11-26，公开资料而非登录实测）：[ChatGPT Study Mode](https://help.openai.com/en/articles/11780217-using-study-mode-in-chatgpt) 已覆盖材料、引导与反馈；[Gemini Study Notebooks](https://blog.google/innovation-and-ai/products/gemini-app/gemini-study-notebooks/) 已有诊断、个性化学习和进度；[Gemini Notebook](https://blog.google/innovation-and-ai/products/gemini-notebook/three-tips-study-gemini-notebook/) 已有材料驱动学习与多题型；[Gemini exam help](https://blog.google/products-and-platforms/products/education/helping-students-and-parents-prepare-for-the-final-exams-period/) 明确支持口头解释并找逻辑缺口。GitHub 近邻：[curio](https://github.com/jo2234/curio)、[learning-tutor](https://github.com/jadrianlg16/learning-tutor)、[lucid](https://github.com/hexa3/lucid) 声称覆盖 teach-back、证据或学习状态；借鉴方法，未验证可替代本产品，未执行第三方代码。不要宣称费曼式 AI 教学、自动出题或知识档案为独有创新。

### 0→1 产品及技术架构

- 体验层：产品介绍／首次引导与免费示例；首页（继续学习、新主题、待巩固）；主题学习空间（材料、知识点、阅读／对话、讲解、诊断、练习）；待巩固与理解档案；学习记录、设置、帮助、备份恢复。学习动作可自由往返，不强制线性五步。
- 业务层：Topic/StudyGoal → MaterialVersion 与当前选段 → Concept（有稳定 ID、来源定位、适用条件、用户可编辑）→ LearningSession/Attempt（语音或文字、提示使用、确认版本）→ DiagnosticClaim（具体主张、状态、来源与回答证据）→ Gap（待解决问题及下一动作）→ Practice/IndependentAttempt（新情境、提示情况、评判依据）→ EvidenceEvent/DerivedState（可追溯状态与恢复位置）。字段名仅建议，先映射现有 schema，避免平行重复存储；保留旧记录的真实语义，不倒推未有证据的知识状态。已有材料谱系、引文、草稿、备份、条件反馈和独立作答优先复用。
- AI 层：材料提取和可编辑概念候选、Tutor、ASR、对照诊断、补学建议、针对性练习生成与独立评判；固定 schema 和来源版本，校验引用存在及适用条件；按需构建有限上下文。模型不直接改历史，不以语速／停顿判断理解，不把有提示回答标为独立通过。状态由程序根据证据推导；可区分未检验、需巩固、已表达、已独立检验、需重新核对。不用虚构总体掌握度百分比。现有实际模型合同及费用管理复用，离线模拟只能在明示的 demo/test 中使用。
- 工程层：沿用原生前端、Node、Python、IndexedDB 与本机启动方式，先读代码和真实界面再确定模块边界；拆分 UI/状态、领域逻辑、存储与迁移、来源索引、上下文和模型适配、费用/请求管理。避免无收益换栈或整库重写，允许为实际复杂度做重构。历史 v1–v5 备份继续可读，新语义如确需版本变更则显式迁移与兼容。七天到期不续期、12 份逻辑材料、单份及组合 5000 字和只保存选段／定位的原政策仍有效；理解档案与待巩固也不跨越该保留期。长文件先实现受限的重新导入／重新选段方案，全文持久化另行决定。
- 产品闭环层：需求访谈、竞品对照、任务分析 → 可用性原型 → 开发 → 真实任务评价 → 本地版本交付 → 自愿反馈、问题分级 → 优先级再规划。埋点先定义事件和分母，采用当前留存边界内的本地统计或显式导出脱敏研究记录；不增加联网遥测，不以调用量作价值指标。

### 视觉与交互方向：Apple 介绍页 × ChatGPT Desktop 工作台

**最新 UI 要求**：[桌面工作台的设计减法与验收](reviews/2026-11-26-desktop-ui-direction.md)。Apple 官网参考留给介绍和首次体验；正式工作台参考 ChatGPT Desktop 的稳定导航、正文主区、就近动作和按需显示的辅助内容。保留工程模块，弱化界面卡片化；删重复标签、模块自述与无动作的长文案，保留证据、风险、状态和无障碍。基于当前候选版本增量实施，先覆盖回访首页、材料工作台、诊断到局部重讲；不要另开并行实现重做 #45。

参考 [Apple 官网](https://www.apple.com/)、[Mac](https://www.apple.com/mac/) 的短文案、明确焦点、统一节奏与克制的主按钮；[Apple HIG design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)、[layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[typography](https://developer.apple.com/design/human-interface-guidelines/typography)、[UI design tips](https://developer.apple.com/design/tips/) 用于可读性、对齐、反馈及响应式。官网/首体验可用大标题、产品价值叙事、精致模块与轻动效；日常工作台保持高效信息密度，不堆大面积 Hero、巨型卡片、无意义玻璃拟态或动效。使用原创视觉，不复制 Apple 商标、商品图、专有字体/图标资源；Windows 系统字体栈（Segoe UI、微软雅黑等）、合法自有/开源图标。建议初始 token：白 #FFFFFF、暖中性浅灰 #F5F5F7、正文 #1D1D1F、次级 #616168、主色 #0066CC（以实际对比度为准），8px 节奏、12–20px 圆角、细边界、轻阴影，16px 正文；状态带文字不只靠色。视觉方案不是强制逐像素规格，由 Codex 基于可用性优化。

关键页面：① 首体验短价值主张／使用材料／体验示例；② 首页继续学习优先、主题与待巩固摘要；③ 导入/选段预览、来源明确；④ 桌面学习工作台左侧紧凑材料/知识点导航、中心阅读/学习/讲解、右侧可折叠诊断/证据/下一步，区域滚动独立且操作位置稳定；⑤ 讲解录音/文字入口、确认文字、回听；⑥ 反馈先给具体缺口与下一动作，展开原文和原话，减少重复标签/解释；⑦ 练习先答再看反馈，区分有提示和独立；⑧ 理解档案/待巩固聚焦下一项行动而非大屏；⑨ 设置、帮助、保留期、备份、费用状态适时呈现。窄窗/390px 以单列及面板切换适配，桌面先看 1280/1440px 和键盘路径。示例应换成可展示真实课程复杂度的原创合成案例，贯通一轮纠错和迁移题，不冒充实时 AI。

### 0→1 评价、产品指标与交付方法

候选北极星：在规定留存期内每位活跃学习者经新情境独立检验解决的具体缺口数（按唯一 gap/attempt 去重，不把有提示或未核对的结果计入）；漏斗：新建／导入成功 → 首次确认讲解 → 可用诊断 → 执行补学 → 独立作答 → 闭合缺口 → 自愿恢复学习。记录首次反馈耗时、任务完成率、诊断严重误判/遗漏、独立检验前后表现、回访、调用成本。先收集基线与实际分母再设阈值。真实学习效果不从 CI、模拟 demo、单次助手评分推断。

## GitHub 交接约定

用户希望 Chat 与 Codex 直接在 GitHub 接续工作，减少展示和人工转述。

1. 开始时读取 `meta/master-state` 的 CURRENT_STATE 与 HANDOFF，并记录所依据的 MASTER commit、产品基线和当前任务。产品 checkout 的旧副本只作指针。
2. 每个有意义批次在产品分支沿用 `docs/iterations/YYYY-MM-DD-主题.md` 写一份简洁实现／运行报告。相关 PR 可共用一份；已有报告继续更新即可。
3. 报告说明本轮实际完成的用户行为、解决与仍存在的问题、必要取舍、实际执行及复用的验证、未验证内容、对应代码版本／PR／CI、接续任务和阻塞。失败与未解决事项留在记录里。字段可按内容合并，不补空表，不复制全项目历史。
4. 完成推送／合并后，把准确版本、报告和 CI 链接回写 CURRENT_STATE；HANDOFF 保留接下来要执行的内容。更新前核对远端最新状态，保留并发的新决定，不用过期副本覆盖。
5. Chat 审查本轮变化与证据，反馈分 Must Fix / User Decision Needed / Future Optional，并直接写回 MASTER。能自行修复的继续推进；向用户只报告有意义的进展或需决策的事项。

GitHub 只保存允许公开的代码、合成案例、脱敏结论及适量必要证据；学习者原件保留既有私有位置。发布报告、排队、执行中、已合并分别按实际状态记录；无执行回执时不写“已完成”。交接文档本身不证明已启动桌面 Codex。


## 反馈分类与决定边界

**Must Fix**：两模型仍存在关键数字和术语误听，保留文字确认并先听审关键样本；不把技术兼容或合成文本评审称为生产迁移／真实质量已通过。持续按期限推进已明确的维护工作。

**User Decision Needed**：生产切换及整段回听取舍、全文持久化范围。本轮比较授权已执行完毕，任何新增付费比较需另行具体批准。个人原件外传、数据政策或公开部署仅在具体方案获准后执行。

**Future Optional**：独立模型复核、向量检索、整库媒体优化、云同步、多 Agent 产品形态。按实际证据安排。
